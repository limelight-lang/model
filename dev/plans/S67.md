# S67 — A web-server load on the rig

Notes of the stage in `PLAN.md`; deleted with it. [F] marks a figure a cited
source measured, [A] an assumption to be swept, [code] a figure of this crate.

## Why the rig's loads decide no scheme (the loads' Critic, 2026-09-27)

- The paced wait calls `ll_gc_maybe_collect` every 1 ms
  (`worker/tests/the_rig.rs`, the paced loop), so a rig mutator is idle and
  consenting nearly all the time: `garbage-25` is under 0.5 % busy,
  `live-churn` 2–8 % (estimated from its instructions). No mutator waited for
  its token in S65.28 or S65.32, so the 10 % share rule was read over zero
  waits. A server worker blocked in `accept` or on a database read makes no
  poll (`rfc/model/gc/rc-cycle.md`, an owner asleep).
- `garbage-25` and `registered-ring-live` exercise fate "a" and a live set of
  47–63 roots, which costs the same in every scheme
  (`dev/OPERATION-COUNT-BY-SCHEME.md`, 3.2); `deferred-then-dead`'s last free
  is X. The long-iteration gate is below its own noise: `garbage-0`, with no
  collector, read 17 against 3.
- `live-churn`'s result is set by `FALLBACK_INTERVAL_MIN` and
  `BATCHES_PER_EPOCH`, neither measured, and by one ratio T/E ≈ 1.25.
- Rings of 6 disjoint members, against a corpus whose median candidate
  closure is 381 of 381 objects, every root reaching the service container
  (`rfc/model/gc/cycle/questions.md`, the corpus); the loads with overlap
  never start a collector.
- `standing_bytes` is one sample of a sawtooth, in 128-byte members with
  nothing hanging from them.
- The metric is the mutator's instructions only; the collector's CPU and the
  cache misses of header touches are printed and not scored.
- Every death in the churn loads is silent (the keeper's edge lands on the
  registered root); every death in the garbage loads registers a root.
- The loads register at most about 16k roots a second a mutator.

## The loads

Two variants, because where a request's memory lives decides the load.

**`web-arena`**, the design's main path: request objects live in the
request's arena, which no collection scans (`rfc/model/memory/arenas.md`),
and a heap reference stored into it is released once at the reset
(`Arena::log_release_at_reset`, `reset`).

**`web-heap`**, the fallback where escape analysis fails: the request graph
is in the GC heap.

### Common to both

| parameter | value | basis |
| --- | --- | --- |
| mutators | 8 | one worker per core, Octane's default [F] |
| collectors | cap 1 and cap 4 | 4 is the crate's default [code] |
| requests in flight per mutator | 1; an async variant 64 | PHP's worker model [F]; [A] |
| arrivals | open-loop Poisson, the rate set to 60 % mutator CPU in an A/A cell | [A] |
| request CPU | lognormal, median 4 ms, σ 1 | [A] |
| blocking I/O waits | 2 a request, lognormal, median 3 ms, σ 1 | [A] |
| during waits and between requests | the mutator sleeps and makes no poll | the first finding above |
| polls inside CPU phases | about every 50 µs | [A] |

### Long-lived state per mutator

- A core of 5,000 objects in one strongly connected graph; the corpus's 381
  is a lower bound [F], ten times that a real application [A].
- An LRU object cache of N values, each 10 objects with a back-edge [A], a
  90 % hit rate [A]: a hit is a non-final decrement that registers the value
  once, a miss evicts a value that dies silently. N ∈ {10k, 40k, 150k}, which
  brackets H's 32,768 re-reads an epoch and D's 65,536
  (`dev/OPERATION-COUNT-BY-SCHEME.md`, 2.4 and 3.4). Discord's scan of a
  large LRU cache is the published pathology [F].
- 1,000 sessions of 20 objects with one cycle each [A], an idle lifetime of
  1,440 s (PHP's `session.gc_maxlifetime`) [F], scaled to the cell.

### `web-arena`, a request

- Its objects in the mutator's `Arena`, reset at the request's end; they
  register nothing.
- 300 heap references stored into arena containers and logged for release at
  the reset [A]: their releases are non-final decrements on core and cache
  objects.
- Escapes at the reset: a session write on 30 % of requests, a cache insert
  on 10 % [A].

### `web-heap`, a request

- Objects: lognormal, median 10,000 [A], between Discourse's 38,363 a request
  and Laravel's 0.66 MB hello-world peak [F]; sizes 50 % 64 B, 35 % 128 B,
  15 % 512 B, about 1.4 MB a request [A].
- A context cycle of 8 objects the request tree hangs from, fan-out 8
  (Express's `req.res`/`res.req`, Octane's `clone $this->app`) [F]; 0–3 ORM
  collections of 10–100 entities with child-to-parent back-edges [A];
  closures 45 % of the objects (179 of 381 in the corpus) [F], each with an
  edge to the context or the core; 1 % of payload objects hold an edge into
  the core [A].
- Registrations: 10 % of objects get a non-final decrement at a uniform point
  of the request's life, swept 2/10/30 % [A]; 99 % of objects never exceed a
  count of 2 (Shahriyar et al.) [F]. The context root registers at the start.
- At the request's end the context's last external reference lands on the
  registered root in 50 % of requests, a silent death, and on an unregistered
  member otherwise, which registers a root; swept 0/50/100 % [A].

### Cell length

60–120 s, the TTLs scaled so that half the cache turns over inside a cell,
the first two epochs discarded.

## The protocol (draft for S67.1's Critic)

- Primary metric: CPU cycles a request, the mutators'
  (`mutator_cycles_in_the_loop`) and the collector's (`collector_cpu_us`)
  together.
- Gates: mean garbage from the integral at most 1.10 × the baseline's; peak
  garbage (a new column) at most 1.25 ×; `withheld_by_an_entry_mean_bytes`;
  `ledger_peak_bytes`; request latency p99 and p99.9 per request, with the
  slack set from A/A cells; `token_wait_longest_us`; completion in the drain.
- Reported beside: the token-wait and withheld-return shares, `roots_batched`,
  `turnovers`, and deaths split into silent, completed and born garbage.
- Deciding: `web-arena` at N = 40k and 150k, `web-heap` at one point,
  `deferred-live-large` and `live-churn-dies-by-count` as controls. Guards,
  bounding a loss at 5 %: `garbage-25`, `registered-ring-live`, `garbage-0`.
- A/A cells, five repeats, the arms' order rotated. The arms are the two
  schemes Edmond keeps until this run (2026-09-28): D the baseline and HG the
  candidate, each in its best build as S65.42 and S65.43 leave it
  (`wait-by-readings` with or without S65.43's release, by S65.43's
  verdict), and D and HG without the waits beside them. H without
  `hold-by-generation` is not an arm: under the waits that build is refused
  (`compile_error` in `cycle/mod.rs`).

## S67.1's Critic, 2026-09-28 (answers owed before the rule is fixed)

1. No verdict function: no win threshold, no tie outcome, no mapping to "drop
   D" or "drop HG"; the best builds differ 0.2–1.9 % in instructions on the
   rig, inside the spread, so every cell reads a tie.
2. The loads make best D and best HG cost the same by construction: request
   CPU (4 ms median) dilutes the scheme's work below 0.1 % of cycles, and the
   request-garbage path is D's in both schemes (fate "a"; a root read in its
   first epoch goes D's way in HG).
3. 60 % mutator CPU is unreachable at one request in flight (mean CPU 6.6 ms
   against 9.9 ms of waits: 40 % at most), so open-loop arrivals overload;
   p99.9 of the CPU draw alone is ~88 ms, far above the collector's 1–2 ms.
4. N does not set the registered population (lookups per request unstated);
   half the cache turning over in a cell contradicts a 90 % hit rate; the
   32,768 / 65,536 bracket is of the builds without the waits.
5. In `web-arena` the epoch likely turns by X, which releases every wait, so
   the best builds read as the builds without the waits there.
6. Cycles in the loop and collector µs over its whole life are neither one
   unit nor one window; cycles are noisier than instructions; new instruments
   are needed (requests, arrivals and latency from arrival, garbage bytes by
   size, deaths split by kind, windowed collector counters).
7. A bare `Arena::reset` drops escaped objects (use after free);
   `promote::arena_reset_full` is the entry, and its retained blocks pin
   64 KiB each, which a garbage gate in object bytes does not see; a reset's
   release can be the final one.
8. Gates with no bound, ratio gates with no absolute floor, a drain length
   unnamed (the waits' last free is 8.4–8.6 s), guards equal in every scheme.
9. Five repeats resolve 12–17 %, not the 0.2–1.9 % between the best builds.
10. The arms read two ways (S65.43 per scheme?; builds without the waits
    deciding or reported?); PLAN.md names H, the notes drop it; `web-heap`'s
    point, per-request object counts and edges into the core unnamed; no
    spare-core placement with 8 mutators on 8 cores.
11. Run length: ~6.5 h minimal, ~19–38 h with the sweeps, with no rule for
    voiding a cell under another job's load.
12. Unswept assumptions that decide: the poll interval, the request CPU,
    lookups per request, reach into the core, releases per request, escape
    rates.
13. [F] marks: 179/381 is 47 % and a boot heap, not a request's make-up; "381
    a lower bound" and "ten times" are not the source's; Shahriyar's 99 % is
    DaCapo's "for many benchmarks".
