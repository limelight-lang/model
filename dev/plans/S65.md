## S65.29 — The cross-thread frees a grant withholds

**What stands.** An entity slot another thread frees is pushed onto its
block's remote stack (`Heap::free_remote`). The owner takes the stack back
only in `Heap::collect_remote`, and that call refuses while a trace holds the
owner's returns (`deferred_slot_reuse::returns_are_withheld`). None of the
three marks counts these slots: they are on no stack of the owner's, and the
owner never learns how many arrived. So a producer freeing into the owner's
blocks under a long grant grows the owner's heap by a whole pool block every
time the owner's own blocks of a class are full, without the grant ever
being recalled.

**The choice (option 1 of the step, the Critic's form).** The kept frees
count toward the deaths' mark slot by slot. Under a foreign holder,
`Heap::collect_remote` swaps the block's remote stack off as it would to
collect it, and instead of putting the slots on the block's free list it
puts them on the deaths' stack the owner's own frees wait on, counted there
toward `DEATHS_MARK` (`deferred_slot_reuse::withhold_remote_frees`). The two
stacks link through the same word, so the move walks the chain once to count
it and re-store each link as the release the deaths' stack is read by. `used`
still counts each slot, and the drain's hand-back frees it as an ordinary
